# ReViveX Ransom 技术说明（高级用户）

面向技术人员：各恢复方式的细节、能力边界、命令行与构建。普通用户请看 [README](../README.md)；恢复原理见 [原理说明](原理说明.md)。

**0.2.0 为待验证版本，尚不能视为已完成的正式发布；此前 0.1 源码快照不是最终版本。** 当前提供中文/English、浅色/深色桌面界面和命令行引擎。Windows 安装包须通过冻结程序及安装/卸载检查后发布；没有发布资产时从源码运行。GB/TB 真实受损镜像的速度、内存峰值和恢复率尚未验证。

首次测试请先阅读[大镜像测试指南](../build/TESTING-0.2.md)，完成轻量诊断，再决定是否读取文件内容。

## 自动恢复（推荐）

“恢复方式”第一项“自动恢复（推荐）”是默认选项。只需选择源文件和恢复结果保存位置；可以再选一个**快速临时目录**（例如 C 盘 SSD）存放中间数据，然后点“开始自动恢复”。

程序先只读诊断，再自动选择路线：

| 诊断结果 | 路线 |
| --- | --- |
| VHDX 头部、区域表和 BAT（块映射表）有效 | 逻辑 NTFS 元数据索引（同“VHDX · 逻辑 NTFS 文件”） |
| 映射被破坏或加密，但抽样探测发现明文 NTFS 元数据 | **重建块映射**，按原始文件名和目录恢复 |
| 以上都不是 | 原始特征雕刻（ZIP / NTFS 驻留流 / PNG / SQLite，无法得知原名） |

重建路线共 11 个阶段，界面显示“阶段 i/11 · 名称”、字节或条目进度和计数：

1. **只读诊断**：头部签名、Gentlemen 尾标、推断加密区间；不做全盘哈希。
2. **抽样探测**：在明文区抽样读取，判断 FILE/INDX 记录是否幸存（约一分钟内）。
3. **证据扫描**：顺序读一遍源，只保存 FILE 记录、INDX 块、文件头签名、全零 MiB、NTFS 引导扇区和 VHDX 元数据表；每 30 秒写检查点，中断后截回检查点继续，不重复。推断的加密区间放在最后扫描，不跳过。
4. **证据索引**：把证据解析进 SQLite，只读证据目录，不再读源。
5. **重建块映射**：簇大小、块大小、每个卷的分区偏移都从证据推算（INDX 精确锚点 + 文件头命中），不需要手填参数，推算过程写入报告。块大小宁小勿大：只有在多个独立证据支持、且没有任何反证时才采用更大的块。
6. **卷归属判定**：按 MFT 片段的文件头吻合率区分本卷记录和卷内镜像文件（.vhdx/.img/.bak 等）自带的记录，镜像内的记录不会混入结果。
7. **缺块匹配**：对缺少映射的块，只用能逐字节核对的证据（ZIP 成员 CRC、PNG 分块 CRC、PDF 对象偏移、多个文件头）；**所有证据都吻合且唯一**的候选才接受，平局一律拒绝。正式使用前先在已知块上自检，自检出现一次误判就停用本轮匹配。候选位置按物理顺序一次读完，避免随机读。
8. **命名提取**：只写出每个块都有可信证据的文件；父目录必须序列号一致且确为目录，否则放在 `_上级目录名丢失_<记录号>` 下；驻留在 MFT 中的小文件直接从证据写出并最先写；排他创建，从不覆盖。
9. **分级校验**：可用 / 待确认 / 疑似损坏。JPEG 会扫描整个压缩数据，不只看头尾；另检查 PNG、PDF、ZIP/Office、OLE、TIFF、SQLite、PE、MP4、GIF、文本。
10. **整理结果**：移动到 `最终结果\可用|待确认|疑似损坏|缩略图缓存\<卷>\<原路径>`。只移动不删除，每次移动记录在 `最终结果\_整理记录.tsv`，可用 `revivex_organize.py --undo` 全部撤回。
11. **汇总**：写出 `清单.jsonl`（每个文件的原路径、输出位置、大小、SHA-256、分级）、`未恢复清单.jsonl`（未写出的文件及原因）、`auto_manifest.json` 和 `结果说明.txt`。

- **已删除文件**：重建路线同时恢复 NTFS 中标记为已删除、但数据簇尚未被现有文件占用的文件，写到 `最终结果\已删除文件\<可用|待确认|疑似损坏|缩略图缓存>\<卷>\<原路径>`，与现存文件分开、互不覆盖；数据簇已被其他文件占用的，列入 `未恢复清单.jsonl`（原因 `deleted_clusters_reused_by_existing_file`）。空闲簇也可能曾被覆盖后又释放，因此已删除文件同样经过分级校验，“可用”只代表结构完整。命令行 `--skip-deleted` 可关闭。
- **丢失文件**：镜像头部、映射表被破坏或加密、文件因此“丢失”时，只要 NTFS 元数据仍为明文，即可按原名恢复（重建路线）。普通磁盘镜像（.img/.dd 等，非 VHDX）找到 NTFS 元数据时同样走重建路线，包括已删除文件。映射完好的 VHDX 默认走逻辑索引，不含已删除文件；需要找回其中已删除的文件时，命令行加 `--route rebuild`。
- **取消与继续**：“安全取消”随时可用。在“结果与验证”打开该任务后点“继续上次任务”（或命令行对同一输出目录再次运行），已完成的阶段不再重做，长时间的证据扫描不会重读。源文件和扫描选项必须相同。
- **临时目录**：证据、索引、块映射写到临时目录；恢复出的文件始终写到输出盘。临时目录大小取决于 MFT/INDX 记录数量；剩余空间低于保留值时停止并保留检查点。不选则放在任务目录的 `_work` 中。
- **资源限制**：界面上的单文件/总输出上限只作用于原始特征雕刻；重建路线以输出盘剩余空间为界（默认保留 4 GiB）。
- **内存**：重建路线在内存中保留全部捕获的 MFT 记录与目录项，占用随记录数增长；数百万文件的源请使用内存充足的机器。
- **结果页**：清单逐行流式导入，几百万条记录不会一次读进内存；状态筛选可按“可用 / 待确认 / 疑似损坏 / 缩略图缓存 / 未恢复”查看，所选文件导出时重新核对 SHA-256。

这仍然不是解密：落在加密区内的数据和 MFT 记录无法按原名恢复；分级只说明结构，不证明内容与原件一致或文件安全。

## 桌面版使用

1. **macOS（Apple 芯片）**：从发布页下载 `macos-arm64.zip`，解压后打开 `ReViveX-Ransom.app`。该版本未经 Apple 签名和公证，首次打开若提示无法验证开发者，请到“系统设置 › 隐私与安全性”点“仍要打开”（压缩包内附说明）。**Windows**：从发布页下载 `windows-x64-setup.exe` 安装到当前用户目录，或完整解压 `portable.zip` 后运行其中的 `ReViveX-Ransom.exe`。免安装版需要同目录的 `_internal`，不能只复制一个 EXE。安装包未签名，不需要管理员权限。
2. 在“恢复文件”选择源文件副本、恢复方式（默认“自动恢复（推荐）”，见上节）和健康独立存储上的工作区。“VHDX · 逻辑 NTFS 文件”只建立元数据索引，不预先提取全部载荷；所选文件在导出时从未改变的源镜像读取。ZIP、雕刻及原始驻留等其他恢复模式会先暂存数据，所有模式都可能写入报告/索引，请预留空间。
3. 在“结果与验证”按目录、文件类型或全部文件浏览，结合搜索和状态筛选。勾选共享同一份选择状态；“全选可导出项”覆盖整个任务，“选择筛选结果”只选择匹配的可导出项，两者都不限于当前页。失败和未支持记录仍可见，但不可导出。
4. 点击“导出所选文件”，选择新的目标目录。只提取/复制已勾选且可导出的文件，查看单独的“导出报告”；扫描状态、记录状态和导出结果相互区分。任务工作区保留，不自动清理。
5. “打开已有任务”重新打开持久化工作区。对于已中断、可继续的逻辑元数据会话，“继续索引扫描”在身份/选项校验后从检查点继续，建立新任务并保留旧会话；这不是所有恢复模式的通用断点续扫。
6. 查看“任务摘要”“记录详情”“导出报告”；“验证输出”只复核支持的报告及文件。校验通过仍不代表原始内容真实、完整或安全，原始总文件数保持未知。

ZIP 中保存的目录路径可保留；逻辑 NTFS 模式会校验目录记录及引用关系，保留可验证的目录（含空目录）。原始字节驻留扫描中的父关系路径仍是推断值，缺失/冲突会保留不确定性。特征雕刻无法知道原始目录和名称。不要把浏览树当作完整原目录恢复。

## 当前能做什么

- ZIP：从本地文件头抢救仍完整的 Stored/Deflate 条目，校验长度及 CRC32，处理部分数据描述符和 ZIP64 信息；受损条目会记录失败，不保证整个压缩包修复成功。
- PNG / SQLite：按文件特征扫描候选数据，并做结构、校验或数据库完整性验证；设置单文件、总输出和解压上限。
- “VHDX · 逻辑 NTFS 文件”：只读解析固定/动态 VHDX 的头部/区域表 CRC32C、BAT 与范围，读取支持的逻辑 NTFS 卷；支持基记录内碎片化 MFT/数据 runlist、驻留及支持的非驻留流、经验证的目录路径和空目录。备份引导扇区/MFT 镜像回退已有合成测试。这些检查不证明文件内容未被加密或未受损。
- “NTFS · 驻留文件流”：从原始字节寻找有效 FILE 记录，仅抢救驻留数据；不使用完整逻辑文件系统映射，不能据此恢复非驻留文件。
- “VHDX · 结构探测”：仅签名/头部线索，不等于严格 VHDX 读取器验证。
- 轻量诊断 CLI：`diagnose_recovery_source.py` 只读关键元数据，不全盘哈希、不扫描文件载荷；输出映射可用性及未知完整性。可能的勒索加密区间仅为假设，报告不包含源路径、磁盘 ID 或密钥材料。其他恢复报告仍可能包含敏感文件名/路径。
- 已知明文对比：比较用户指定的原文件/加密文件，分析 Gentlemen 格式尾部和推测加密区间。普通 ZIP/NTFS 抢救不要求原文件；只有这个分析功能需要原文件配对。
- 实验性内层 ZIP 抢救：针对指定外层条目的受损 Deflate 流尝试有限的前缀/后缀恢复；需填写精确条目名，结果必须人工复核。
- 结果复核：生成 JSON 记录，对支持的输出重新校验；结构有效不代表内容完整、可信或无恶意。

当前改进包括 ZIP 扫描的活动区间索引与可选内存映射、同名/大小写冲突保护和 `--preserve-duplicates` 单独保存；PNG 调色板索引检查；PNG/SQLite 候选及 NTFS 记录的逐行 JSONL 索引；NTFS 原始 Unicode 名称保留在记录中。

### 0.2 能力边界

| 项目 | 当前状态 |
| --- | --- |
| 固定/动态 VHDX、CRC/BAT 及越界防护 | 已实现并有合成测试；不是全面格式一致性或载荷真实性证明 |
| NTFS 几何 | 当前仅 512 字节 NTFS 扇区、1024 字节 FILE 记录；VHDX 读取器支持 4096 字节几何不表示 NTFS 4K 扇区恢复已实现 |
| 支持的非驻留流、基记录内碎片化 runlist、备份引导/MFT 镜像 | 已实现并有合成测试；扩展记录链不包含在内 |
| 稀疏/未初始化数据 | 显式区分元数据定义的零区间；分配边界、空文件及备份回退已有合成回归测试，不把不可读区间猜成零 |
| 磁盘 SQLite 元数据会话、CLI 续扫及按需所选导出 | 会话核心及桌面/工作区集成已有测试，涵盖中断/崩溃/WAL/身份校验；非所有模式通用续扫 |
| VHDX 映射被破坏但来宾 NTFS 为明文（自动恢复重建路线） | 已实现，有合成端到端测试（破坏头部/区域表/BAT/元数据、乱序块、双卷、卷内镜像、记录号复用）；现场恢复用的是原型脚本，本版本尚未在真实 TB 级源上复测 |
| 活动 VHDX 日志、差分 VHDX/AVHDX 父链 | 拒绝；不回放日志、不合并差分链 |
| 已删除文件（NTFS 记录已标记删除） | 自动恢复重建路线：数据簇未被现存文件占用时恢复到“已删除文件”目录，有合成测试（空闲簇、被复用簇、驻留小文件）；“VHDX · 逻辑 NTFS 文件”等其他方式不恢复已删除文件；不保证内容未被覆盖 |
| NTFS ATTRIBUTE_LIST/扩展记录、压缩、EFS、重解析点 | 重建路线会合并扩展记录中的 $DATA 片段，缺扩展记录则不写出；压缩、EFS、重解析点未实现；不得将跳过结果计算为成功 |
| PDF、JPEG、通用数据库恢复 | 无原名的格式雕刻目前仅 PNG/SQLite；重建路线按原名恢复任意类型，并对 JPEG/PNG/PDF/ZIP/OLE/TIFF/SQLite/PE/MP4/GIF/文本做结构分级 |
| 原始总文件数、完整恢复率、可启动 VM、全部原目录重建 | 无法保证，整体完整性保持 unknown；雕刻原始文件名/目录未知 |

实现依据：[Microsoft MS-VHDX](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-vhdx/83e061f8-f6e2-4de1-91bd-5d518a43d477)、[Dissect NTFS 属性 API](https://docs.dissect.tools/en/latest/api/dissect/ntfs/attr/index.html)、[MFT API](https://docs.dissect.tools/en/latest/api/dissect/ntfs/mft/index.html)。这些是格式/解析器参考，并非对本工具功能或恢复效果的认证。

## 部分 BAT 高级模式（默认关闭）

严格映射仍是默认。仅对 VHDX，可在“VHDX · 逻辑 NTFS 文件”勾选“尝试部分 BAT 映射（高级）”，或给 `recover_vhdx_files.py` / `revivex_scan_session.py` 添加 `--allow-partial-bat`。该功能已通过独立回归测试，但只保留能独立验证的 BAT 映射；无效、冲突及未知区间仍不可读，不猜测位置、不补成零。

关键头部/区域表/元数据校验不放宽；活动日志和差分链仍拒绝。raw 来源不接受此开关。部分映射会明确报告 `partial_bat`、`logical_mapping_complete`，会话可显示 `finished_with_errors`，整体内容完整性仍未知。续扫必须保持相同开关值；首测保持默认关闭，只在理解严格模式失败报告后另建任务尝试。

## 元数据会话 CLI（0.2）

与旧的 `--metadata-only` 一次性盘点不同，`revivex_scan_session.py` 把进度和候选元数据存入健康目标盘的 SQLite 会话，不先提取所有文件载荷：

```powershell
.venv\Scripts\python src\revivex_scan_session.py "C:\Evidence\disk.vhdx" "E:\Recovered\session-new" --source-format vhdx --max-records 10000
.venv\Scripts\python src\revivex_scan_session.py "C:\Evidence\disk.vhdx" "E:\Recovered\session-resumed-new" --source-format vhdx --max-records 10000 --resume-session "E:\Recovered\session-new\session.sqlite"
```

续扫用于未完成的会话，不会突破原 `--max-records` 上限；提高上限需另开新会话。续扫必须使用相同源与精确相同选项，并指定新输出目录；程序验证源 stat、容器/NTFS/MFT 元数据，再通过 SQLite backup 复制旧会话，保留旧工作区。**这不是全源内容哈希**，不能证明每个载荷字节没变化。不要在扫描进程运行时手工复制一个 `.sqlite` 文件而漏掉 WAL；请保留完整工作区并使用支持的续扫入口。

中断恢复、崩溃回滚、WAL 安全复制、源/选项变化拒绝和按需导出的核心已有测试。一项合成 1 TiB 逻辑 VHDX/512 GiB 候选测试只读了不足 128 KiB 逻辑数据、Python 分配峰值不足 16 MiB；这只证明该测试布局的元数据路径有界，不代表真实镜像速度、完整进程内存或恢复成功率。桌面重新打开、继续扫描和按需导出集成亦有回归测试；仍需干净 Windows 与真实镜像验证。

## 重要限制与安全使用

本工具不能通用解密勒索软件，不能从已知明文推出 X25519 私钥，也不承诺恢复率、文件完整性或虚拟机可启动。没有运行勒索样本、联网上传证据、默认扫描所有磁盘或申请管理员权限的必要。

1. 先停止向受影响介质写入，保留原件；在副本或只读镜像上操作。
2. 输出使用另一块健康磁盘上的新目录，预留足够空间。不要把恢复结果写回待恢复介质。
3. 对未知文件保持隔离；不要直接执行恢复出来的程序、脚本或宏。
4. 先用小样本测试并阅读 JSON 报告。限制到达、跳过、损坏和失败不应被当作成功。
5. Windows 构建没有数字签名。不应为了运行它关闭杀毒软件或绕过系统安全警告。

```powershell
.venv\Scripts\python src\recover_vhdx_files.py "C:\Evidence\disk.vhdx" "E:\Recovered\metadata-new" --source-format vhdx --metadata-only --max-records 10000
.venv\Scripts\python src\recover_vhdx_files.py "C:\Evidence\disk.vhdx" "E:\Recovered\logical-new" --source-format vhdx --max-records 10000 --max-file-bytes 1073741824 --max-total-bytes 4294967296
```

桌面入口也支持不加载 Qt 的 `revivex_desktop.py --diagnose SOURCE --report NEW.json`；冻结版可用 `ReViveX-Ransom.exe --diagnose SOURCE --report NEW.json`，以报告文件为准。诊断退出码 2 表示映射不可用或尚未验证，不代表已经恢复；查看 JSON。这里的 `--metadata-only` 是一次性元数据盘点，不是已验证的断点会话。示例导出上限为单文件 1 GiB/总计 4 GiB，超过上限的结果会被限制，不能认定没有更多文件。不要直接以无限范围开始 TB 级完整提取。

这些盘符只是示例，不是程序默认值。Linux/macOS 可使用 `python3 -m venv .venv`，并把解释器路径换成 `.venv/bin/python`、文件路径换成实际路径。NTFS 解析不需要挂载或修改源镜像。

自动恢复（与界面相同的流程）。输出目录必须是新的，或是之前自动恢复的目录（此时从检查点继续）：

```powershell
.venv\Scripts\python src\revivex_auto.py "E:\Evidence\disk.vhdx.locked" "F:\Recovered\auto-new" --work-dir "C:\ReViveX-work" --progress "F:\Recovered\auto-progress.json"
```

只在需要撤回整理（把文件移回提取位置）时运行：

```powershell
.venv\Scripts\python src\revivex_organize.py "F:\Recovered\auto-new" --undo
```

可选参数：`--damaged-range START-END`（已知损坏区间，可重复，与尾标推断区间合并）、`--block-size-mib`（覆盖推算的 VHDX 块大小）、`--reserve-mib`（输出/临时盘保留空间）。`revivex_organize.py` 不带 `--undo` 时重新整理。

已知明文分析与实验性内层恢复：

```powershell
.venv\Scripts\python src\analyze_gentlemen_pairs.py "C:\Evidence\target.enc" "E:\Recovered\analysis-new.json" --pair "C:\Evidence\original.bin" "C:\Evidence\original.bin.enc"
```

`--pair` 可重复指定。`--outer-member` 必须是归档中的精确相对条目名。每个脚本支持 `--help`；查看当前参数、资源上限以及实验功能约束。Gentlemen 特定区间排除只应在格式已确认时使用 `--gentlemen`，其范围是推测值。
