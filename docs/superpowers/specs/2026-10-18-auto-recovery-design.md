# 自动恢复与大镜像性能设计

## 目标与现场约束

在恢复方式菜单第一项增加默认选中的“自动恢复（推荐）”。用户仅需选择源文件与输出位置；现有手动方式保留为高级选择。沿用已修复的自适应单页布局，不增加整页滚动。目标机器 E:\<受害镜像>.vhdx.<勒索扩展名> 只读；程序、索引、临时文件、报告与导出全部位于 F 盘新目录，禁止改源属性/ACL、挂载修复、写回 E 或修改旧工具目录。

当前程序只有单任务隔离调度，尚无自动恢复；ZIP 默认 2 GiB 输入上限，raw resident/carve 整源 mmap 也不适用于本机 17 TB 证据。不能仅增加菜单文字并循环现有七个命令就宣称实现自动恢复。

## 三种方案

1. 推荐：轻量诊断路由 + 原始字节共享扫描。有效映射先做逻辑元数据索引；映射不可用或逻辑扫描有缺口时，进行共享的原始字节候选扫描，再按候选类型验证、提取，统一目录与来源记录。
2. 原有引擎逐项串行：实现快，但多次读完整镜像，且继承 mmap/输入上限问题；不适用于此现场。
3. 所有引擎并行：同盘读竞争、资源占用、取消与去重复杂；不采用。

## 执行顺序

- 阶段一：只读身份与少量关键元数据检查、输出盘空间检查，记录本次源和选项。只读诊断不进行全源哈希。
- 阶段二：映射有效时执行逻辑元数据索引，保留受支持文件和目录。已建立可用索引且没有已知缺口时，不自动做额外整盘原始扫描；用户可手动选深度抢救。候选不是已恢复文件。
- 阶段三：映射不可用或存在已知缺口时，一次顺序遍历计划扫描范围，寻找 ZIP 本地成员头、受支持的 NTFS FILE 记录、PNG、SQLite 等当前已支持的候选。候选发现与内容验证分开，以原始偏移、验证结果和来源记录关联。
- 阶段四：只有候选满足条件时尝试嵌套 ZIP 专项抢救；受损 DEFLATE 字节不能臆造，无法独立验证的内容不记成功。
- 阶段五：汇总可导出文件、失败、跳过、重复和未支持项，按当前选择/导出流程交付。输出哈希只能证明输出字节一致，不证明原始内容完整或安全。
- 已知明文对比需要外部原件，不自动运行；结构探测属于诊断阶段；不自动放宽 VHDX 头部/CRC/BAT 校验，不猜测非驻留物理映射。

## 性能要求

- 扫描层采用有界 buffered read/read_at，默认顺序读取块约 8 MiB；禁止整源 read_bytes、整源 mmap、复制整源或逐种特征重复扫全盘。跨块保留足够重叠，跨块记录按原始偏移去重。
- 每读一块同时匹配全部支持签名；类型验证器可按需读取候选范围。候选读取是额外 I/O，应计入统计，不能声称全程只读一遍每个字节。维护有界缓存降低重复读取。
- 顺序读取单通道；候选验证使用有界队列和小并发，默认偏保守，根据磁盘实测调整。扫描队列满时背压，不把数百万候选积存在内存。
- 数据流式写入 F；大文件验证不读入整内存；解压炸弹、损坏尺寸、不可验证候选仍有明确资源保护，达到限制需显示原因，不能假报完成。
- SQLite 保存偏移、状态、结果和检查点，批量提交；界面刷新约 0.5–1 秒，不逐候选刷表或整库重读。结果按现有分页机制浏览。
- 检查点仅在已持久化结果以后推进；中断可能重扫最后一小块，靠候选标识防重复。继续前校验源身份、关键证据和选项，明确 stat 不是全源内容哈希。
- 源是否被外部进程修改的检测要在 Windows 单独验证，现有 fstat 变化检测测试有失败记录，不能未经修复依赖该检查启动长期恢复。
- F 盘空间不足、源读取异常、源身份变化时停止后续提取并保留已提交结果；不无限重试，不自动改源。
- Gentlemen 区间只是推测，不能静默跳过并算全盘完成。若采用推测区间跳过优化，必须明确记录“未扫描”，并提供后续补扫入口；默认优先减少重复 I/O，不以未经验证的排除区间换取虚假完整率。

## 界面

菜单第一项“自动恢复（推荐）”，开始按钮“开始自动恢复”；技术选项仍可手选。主界面显示阶段、已扫描/计划扫描字节、当前速度、已验证文件/候选/失败数量。对不确定总量使用字节进度，不显示文件完整恢复率；速度未稳定时不提供 ETA，扫描完成与导出完成分开。后台读取和校验不阻塞界面。取消可用；续扫只对确实实现且验证的阶段开放。

## 验收与实施顺序

1. 首先修复并测试大镜像读取抽象、跨块候选、源变化检测；利用虚拟大文件/小型稀疏夹具验证有界 I/O，禁止 Windows 测试意外实际分配 TB。
2. 在 ZIP/raw resident/carve 中接入有界读取；用既有合成回归验证恢复内容未退化，不机械拼接不连续 VHDX 载荷。
3. 接入自动路由、单次多特征扫描、统一索引与内容去重。相同内容保留不同原始名称/来源关系，不把多个文件名直接丢弃；避免索引阶段与已落盘文件混算。
4. 测试取消/崩溃/续扫、空间不足、损坏候选、不支持模式，确认不写源、不覆盖输出。
5. 接入 GUI 阶段进度；复验中英文、960x640 至 1536x864、150%/200% 缩放，无主页面滚动或按钮溢出。
6. 部署 F 盘，在图形界面运行有界真实范围试扫，报告实际读取字节、墙钟耗时、吞吐、进程内存峰值、候选/验证/提取数与 I/O 放大；性能数值以实测给出，不能以合成测试冒充 17 TB 实绩。
7. 有界试扫通过后，才启动长时间恢复；窗口保持可见，检查点与输出落 F。全盘恢复结果与完整性保持实证描述，不能保证恢复率。
