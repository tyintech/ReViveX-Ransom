# 现场恢复总结与软件改进依据（现场目标机，2026-10-18 至 10-25）

## 1. 现场情况

- 源：`E:\<受害镜像>.vhdx.<勒索扩展名>`，约 17 TB（Windows 显示 15.57 TB），动态 VHDX，Gentlemen `--super--` 尾标。
- 加密只覆盖三段约 171 GB 的区间（文件头、中段、尾段，合计约 0.47 TB）。VHDX 头、区域表和 BAT（块映射表）都在加密区内，原有工具因此判定"映射不可用"。
- 其余约 97% 为明文：来宾 NTFS 的 MFT 记录、目录索引（INDX）和文件数据都在。
- 来宾内有两个 NTFS 卷：A（系统卷，约 20 GB）、B（数据卷，约 14.6 TB）。卷 B 内还存放着 `.vhdx`/`.bak` 等镜像文件，它们自带的 NTFS 记录会混入扫描结果。
- 硬件限制：E 盘顺序读约 300 MB/s，随机读仅 60–110 次/秒；F 盘写入约 55–72 MB/s；C 盘（SSD）写入约 165 MB/s，可用约 460 GB。

## 2. 实际可行的恢复流程（按执行顺序）

| 步骤 | 做法 | 关键经验 |
|---|---|---|
| 1 只读诊断 | 头部签名、Gentlemen 尾标、推断加密区间 | 不做全盘哈希；stat 比较不是内容哈希 |
| 2 抽样探测 | 在明文区抽样，找 FILE/INDX 记录 | 40 秒即可判断 NTFS 元数据是否幸存，应先做 |
| 3 证据扫描 | 一次顺序读全盘，只保存 FILE 记录、INDX 块、4 KiB 对齐的文件头、全零 MiB | 17 TB 约 16–17 小时；每 30 秒检查点；中断可续；检查点文件替换需重试（Windows 会被读取方锁住） |
| 4 证据索引 | 解析记录与目录项到 SQLite | 放在 SSD 上；只读 F 盘证据，不再读源 |
| 5 重建块映射 | INDX 精确锚点 → 32 MiB 槽位网格（偏移 9 MiB）→ 插值 → 文件头验证/搜索 | 卷 A 分区偏移需用文件头命中数重新拟合（19 MiB），不能只看锚点 |
| 6 卷归属判定 | 按 MFT 片段的文件头吻合率区分本卷与镜像内的卷 | 吻合率呈两极（100% / 0–20%），阈值简单可靠 |
| 7 命名提取 | 只写所有块都有证据的文件；路径还原；排他创建；可续传 | 先写小文件（MFT 驻留数据直接从证据中取） |
| 8 路径校正 | 父目录必须序列号一致且确为目录 | 第一版借用了被复用的记录，约 27 万文件路径错误，已修正 |
| 9 分级校验 | 可用 / 待确认 / 疑似损坏；深度校验 TIFF、OLE、SQLite、PE、MP4、文本 | "写出"不等于"恢复成功"，按可用统计 |
| 10 缺块匹配 | 文件结构探针（视频帧、PDF 对象、ZIP CRC）+ 相邻块 + 时间 + 一对一排除 | 先测准确率再使用；改为一次顺序读取候选槽位后速度提升数十倍 |
| 11 整理 | 合并到 `最终结果\可用|待确认|疑似损坏|缩略图缓存` | 只移动不删除，记录可撤回 |

## 3. 失败与教训（必须写进软件）

1. **整源 mmap / read_bytes** 在 17 TB 上直接失败（WinError 1450）→ 全部改为有界读取。
2. **后台无窗口运行**让用户看不到进度、以为停止 → 长任务必须在可见界面中运行并显示阶段与字节进度。
3. **JPEG 弱校验**（只查头尾）确认了错误位置：1,342 个文件中 1,211 个错误 → 弱校验不能用于确认新位置。
4. **相似副本**（同一视频/AI 的多个版本）能让错误位置通过单文件结构检查 → 需要同块其他文件的文件头交叉检查。
5. **留出测试漏洞**：测试时正确位置总在候选中，实际丢失块的正确位置可能在加密区 → 只接受"所有证据全部吻合且唯一"的候选；所有新方法先抽样提取再上线。
6. **路径借用错误记录**：父记录序列号不一致时不得借用。
7. **随机读 E 盘**是匹配阶段的瓶颈 → 规划检查点后按槽位顺序读一遍。
8. **SSH 中断会杀掉子进程**、**计划任务创建失败无提示** → 软件内运行，不依赖远程会话。
9. **Thumbs.db 只剩一个的文件夹**让结果目录杂乱 → 缩略图缓存单独存放。

## 4. 最终可交付形态（软件需要支持）

- 一个"自动恢复（推荐）"入口：选源文件、选输出盘、（可选）选快速临时盘，点开始。
- 自动判定：VHDX 映射有效 → 逻辑索引；映射被加密但 NTFS 明文 → 重建映射流程；否则 → 原始特征雕刻。
- 每个阶段可续、可取消、进度可见，结果按"可用/待确认/疑似损坏"分开，附清单与报告。
- 不写源、不覆盖输出；所有移动可撤回。

## 5. 现场结果（最后一次核对时）

- 卷 B：约 267 万个现存文件，约 12.96 TB（Windows 口径）。
- `最终结果\可用` 2,384,397 个文件（约 4.7 TB）；另有第二轮补充与缺块匹配结果持续追加。
- 缺块匹配：结构匹配确认约 6.2 万块；顺序读取匹配首轮确认 11,915 块；索引块第二轮已启动。
- 未恢复部分主要是落在加密区或缺块未定位的大视频、设计文件；约 35 万个文件的 MFT 记录位于加密区，只能按特征雕刻（无原名）。
